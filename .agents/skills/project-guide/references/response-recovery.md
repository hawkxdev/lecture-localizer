# Completed response compatibility and recovery

The ordinary WAV parser rejects inconsistent lengths. Only the completed HTTP response path additionally recognizes the exact 44-byte PCM1/mono/48000/16bit envelope with RIFF `0x80000023` and data `0x7FFFFFFF`, nonempty whole frames and a physical size below the placeholder. Original bytes remain immutable; only the distinct canonical copy receives actual lengths. A broken transfer remains uncertain, and ordinary finite truncation or another malformed header is refused.

`recover --job DIR --operation ID --attempt N` selects the latest failed invalid-audio attempt of the current request, verifies complete HTTP 200/audio-wav evidence, posted text, signatures and hashes, then publishes a separate local receipt before registering the retained raw artifact. The original operation journal remains byte identical. Repeating recovery is idempotent, including after an interrupted manifest checkpoint. A later operation/attempt, unknown receipt version, corrupted/aliased file or mismatched provenance blocks recovery or reuse. `status` and run reports distinguish the local receipt from original failed-attempt history; a later unresolved attempt cannot be completed by an older recovered response. This operation has no provider transport or credential reader. Command examples belong to README; structural contracts live in the four packaged schemas.
