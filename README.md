# lecture-localizer

A local CLI for localizing lecture videos while preserving the original media.

Provide a local video, matching English SRT subtitles and a reviewed Russian translation. The current version produces an MP4 with selectable original/Russian audio and subtitle tracks. Automated transcription and translation are planned extensions.

**Status:** Development. An installable package with local tool diagnostics, validated persistent jobs, guarded speech synthesis, fitted narration, verified MP4 assembly and the complete guarded run/offline assemble commands is available. The first scenario is accepted on a short macOS reference sample, including reviewed translation, listening, QuickTime/IINA behavior and a 1.20 speed comparison. Long-lecture use, other voices and other platforms remain unverified; review each new output.

## Implemented: `lecture-localizer doctor`

The first stage ships an installable package whose `doctor` command inspects the local media tools and the capabilities the target workflow requires. It never contacts a speech provider and never reads provider credentials.

Requirements: Python 3.12 or later, with FFmpeg, ffprobe and GPAC MP4Box installed locally for full diagnostics.

```sh
git clone https://github.com/hawkxdev/lecture-localizer.git
cd lecture-localizer
python3 -m venv .venv
.venv/bin/pip install .
.venv/bin/lecture-localizer doctor
.venv/bin/lecture-localizer doctor --json
```

Doctor checks that the tools exist and run, and that FFmpeg provides the decoder, encoder and filter features the [approved media profile](docs/specs/001-lecture-localization/spec.md) needs (H.264 decoding, AAC and mov_text encoding, the atempo filter). MP4Box is verified by rewriting track flags on a tiny synthetic input inside a temporary directory. Missing or unusable tools exit with code 7; invalid settings exit with code 3; usage errors exit with code 2. Media subprocesses run with an environment scrubbed of credential variables.

Optional settings can point to specific tool locations:

```sh
LECTURE_LOCALIZER_SETTINGS=/path/to/settings.json .venv/bin/lecture-localizer doctor
```

The settings file is JSON with optional `ffmpeg_path`, `ffprobe_path`, `mp4box_path` and `subprocess_timeout_seconds` keys; unknown fields are rejected. No credentials belong in settings.

Synthetic, rights-safe media fixtures for local experiments and checks are generated by:

```sh
.venv/bin/python scripts/make-synthetic-example.py NEW_DIRECTORY
```

The script refuses to write into an existing directory and creates a deterministic synthetic MP4 (tone and test pattern) plus a two-cue SRT file. It launches FFmpeg with the same credential-scrubbed environment as the rest of the media tooling and therefore needs the package installed in the environment that runs it.

## Spoken English example

From a source checkout or unpacked source distribution, install the package as above and run:

```sh
WORKDIR="$HOME/Movies/lecture-localizer/spoken-example"
.venv/bin/python scripts/make-spoken-example.py "$WORKDIR/inputs"
.venv/bin/lecture-localizer prepare \
  --video "$WORKDIR/inputs/spoken-source.mp4" \
  --source-srt "$WORKDIR/inputs/source.srt" \
  --translation "$WORKDIR/inputs/translation.json" \
  --job "$WORKDIR/job" \
  --output "$WORKDIR/localized.mp4"
.venv/bin/lecture-localizer status --job "$WORKDIR/job" --json
```

Use a fresh directory outside the checkout. The generator downloads three small public LibriSpeech FLAC recordings without an account or token, verifies their IDs, English texts, exact byte counts and SHA256 digests, and creates a 60 second English H.264/AAC test video, matching SRT, reviewed Russian translation, provenance and attribution. It makes no speech-provider calls, reads no provider key and never opens a player. Python, the installed package, FFmpeg with libx264/AAC support and ffprobe are required. MP4Box is also required for the later localization pipeline. The generated example is a constructed demonstration, separate from the tone fixture and from full lecture acceptance.

[Source identities and texts](scripts/spoken-example-v1.json) and [source attribution and terms](scripts/SPOKEN_EXAMPLE_NOTICE.md) travel with the recipe. OpenSLR publishes the corpus under CC BY 4.0; the application's MIT license does not relicense those recordings. Source FLACs, generated media and job data stay outside Git. `example.json` records the actual source digests and tool versions. The public rows endpoint returns current asset URLs; the recorded reference revision is not a claim that the endpoint serves that revision. Any changed source content is rejected. If retrieval fails, the script stops without retries or a replacement recording and leaves an incomplete marker with any already verified files.

Previously downloaded exact FLACs can be reused without network access by passing `--audio-dir /path/to/verified-flacs` to the generator and choosing another fresh destination. Byte checks still apply. Video bytes may differ across FFmpeg versions; the translation always binds to the actual newly generated video and SRT hashes.

Preparation needs no speech key or paid permission. `limits.example.json` describes three requests and 318 translated characters using a dated price snapshot; review current pricing and set your own limits before explicitly allowing a paid `run`. The example file does not authorize spending. Provider output is neither bundled nor needed to prepare and inspect the job. Listening and QuickTime/IINA checks follow on the output of a separately authorized run.

## Implemented: `lecture-localizer prepare` and `status`

`prepare` validates the complete input set and creates or resumes a persistent job directory. It never contacts a speech provider and never reads provider credentials.

```sh
.venv/bin/lecture-localizer prepare \
  --video LECTURE.mp4 \
  --source-srt LECTURE.srt \
  --translation translation.json \
  --job /path/to/job-directory \
  --output /path/to/new-output.mp4
.venv/bin/lecture-localizer status --job /path/to/job-directory --json
```

Run these commands from the repository root, replacing the example filenames and paths with your inputs and fresh destinations. Add `--source-audio INDEX` to `prepare` when the video has multiple audio tracks, and `--settings /path/to/settings.json` when using a settings file. Omit `--json` from `status` for a human-readable report.

`prepare` verifies the video and SRT hashes recorded in the translation JSON, parses source cues by ordinal position, derives positive nonoverlapping segment windows, inspects the actual media streams with ffprobe and requires an explicit `--source-audio INDEX` whenever the input carries more than one audio track. The job directory keeps a versioned `manifest.json`, immutable per revision snapshots of the full translation, the resolved narration text and the source cue text and times, and a one writer `lock` file. Repeated preparation with unchanged inputs reports `unchanged` and writes nothing; changed narration or translation text updates the stage signatures recorded in the manifest so later stages can tell preserved work from work that must be redone.

When the video or SRT bytes change, resumption requires a translation whose source hashes match the new inputs. Supplying that refreshed translation is an explicit rebind: `prepare` accepts it, recomputes the affected windows, fitting, subtitle and container identities from the actual changed inputs, and keeps the earlier immutable revisions and artifacts in place. A translation that still carries the old hashes is rejected. Corrupt recorded cache artifacts make `prepare` fail with exit 3; `status` stays readable and reports the damage. The job directory and the output path must stay outside this application source checkout: job data is never product content, and the distribution gate rejects runtime data found under the package root.

`status` is read only. It reports the recorded binding, media facts, stage states and blocked conditions; a readable job with problems exits 0 while explicitly reporting them. Corrupt or missing snapshots and cached artifacts are reported and never silently reconstructed.

Exit codes follow the implementation plan: 0 success, 2 usage error, 3 invalid input or contract (hash or cue mismatch, unsupported media profile, destination collision, unknown job version), 7 tool or filesystem failure including lock contention, 130 interruption. The output path must not exist and must stay outside the job directory; sources must be distinct files outside the job directory.

Settings files keep the documented tool fields and now accept the job policy fields `fitting_max_speedup` (default 1.2) and the startup track defaults `startup_narration_default`, `startup_original_default`, `startup_subtitles_default` and `startup_subtitles_forced`. Unknown fields are still rejected and no credentials belong in settings.

## Implemented: `lecture-localizer run`, `assemble` and the exit table

`run` executes the complete guarded pipeline over one prepared job under a single writer lock: guarded speech synthesis, PCM normalization, per segment fitting, timeline assembly, narration and original audio preparation, Russian subtitle generation, MP4 candidate assembly, persisted candidate verification and non-overwriting publication.

```sh
.venv/bin/lecture-localizer run --job /path/to/job-directory
.venv/bin/lecture-localizer assemble --job /path/to/job-directory
```

These commands use retained speech artifacts without authorizing new paid requests. If synthesis is needed, `run` stops until you explicitly add `--allow-paid --limits /path/to/limits.json` and supply the required key. Add `--retry-uncertain OPERATION_ID` only for an explicitly approved retry of that exact unresolved operation. To publish an additional output with `assemble`, add `--output /path/to/additional-fresh-output.mp4` using a fresh destination.

Paid requests require `--allow-paid` plus an explicit limits JSON file (`max_requests`, `max_text_chars`, `max_cost_estimate`, `price_per_request`, `price_basis`; unknown fields are rejected) and the `XAI_API_KEY` environment variable. The guards run in that order before any network activity; an unchanged complete cache makes zero provider calls and reads no key. An interrupted or unknown-outcome request stays visibly unresolved in the operations journal and blocks new paid work until the exact operation is retried by ID with refreshed limits; the original receipt is preserved.

Each run writes a durable report under `evidence/` in the job directory with the speech summary, per segment fit evidence, the named verification checks, publication state and the immutable text output paths and hashes (full translation, resolved narration text, Russian subtitles), and separates automated evidence from the pending human checks: listening acceptance, QuickTime Player and IINA startup behavior and translation meaning remain manual review responsibilities and are never granted by a successful run.

The MP4 candidate is built in a staging file on the destination filesystem, verified against the declared prepared sources, registered immutably inside the job, and published through a no-clobber hard link. A durable publication receipt records the actual linked file identity (device, inode, size) together with its SHA 256: an existing output is recognized as this job's result only through that full chain, and any other preexisting file, including a byte identical copy created by another process or a file edited in place, is preserved untouched and reported as a collision. An interrupted publication resumes from the registered verified candidate. `assemble` completes the remaining local work from retained artifacts entirely offline: it may normalize, fit and encode from retained raw responses and rebuild the container, but it never reaches the speech provider, never reads credentials and refuses jobs whose required retained artifacts are missing or corrupt.

The job `status` report now also shows assembly readiness of the prepared units, the publication state (`published`, `pending`, `collision` or blocked) together with the integrity state of the registered candidate, and the latest run report name. Source videos whose bytes fail a full decode stop `run` before any paid request even when their recorded hashes still match. Exit codes follow the implementation plan: 0 success (a readable blocked status also exits 0 while reporting its problems), 2 usage error, 3 invalid input, settings or job contract including destination collisions, 4 paid execution denied before any request, 5 provider or transport failure including unresolved uncertain operations, 6 speech fitting refusal or failed candidate verification, 7 tool, media process or filesystem failure, 130 interruption. Settings are loaded from `LECTURE_LOCALIZER_SETTINGS` for tool paths and subprocess timeouts; the job policy recorded at prepare time governs run.

## Implemented: offline response recovery

`recover` explicitly revalidates one retained failed speech response. It makes no provider request, reads no key and preserves the original `operations.json` and failure verdict. Select the exact operation and attempt reported by `status` and its journal:

```sh
.venv/bin/lecture-localizer recover --job /path/to/job-directory \
  --operation OPERATION_ID --attempt 1
.venv/bin/lecture-localizer assemble --job /path/to/job-directory
```

Recovery requires the latest failed `invalid_audio` attempt of the current segment and request, a complete recorded HTTP 200 `audio/wav` response, matching text provenance and intact retained bytes. A later operation or attempt, uncertain transport outcome, changed request, missing/corrupt evidence or an escaping/symlink path is refused. No automatic paid retry is implied.

The ordinary WAV parser remains strict. After a complete HTTP response, the speech adapter also recognizes one narrowly defined 44-byte PCM envelope: mono, 48 kHz, signed 16-bit samples, RIFF size `0x80000023` and data size `0x7FFFFFFF`, with nonempty whole sample frames below that declared size. It preserves that response verbatim and derives a separate canonical WAV with actual lengths before normalization. Other malformed or truncated WAV bodies remain failures. Recognizing this envelope does not prove that every word was spoken; listening remains a separate check.

Local recovery stores a strict version 1 receipt under `evidence/recoveries/`, binds the exact historical attempt, source, request and artifact hashes, and retains its separately derived WAV under `evidence/canonical-wav/`. The receipt is published before the manifest checkpoint, so repeating the same recovery safely finishes an interrupted checkpoint without another request or changing the original HTTP history. `status` and run reports show local validation separately from failed provider-attempt history; missing or inconsistent recovery provenance blocks reuse. Unknown receipt versions are rejected rather than migrated.

## Workflow

1. Provide a local video, source subtitles, and a reviewed translation.
2. Keep the complete translation separate from the text prepared for narration.
3. Review speech timing before assembling selectable audio and subtitle tracks.
4. Resume interrupted work and inspect an output verification report.

The approved scenario and its acceptance criteria are specified in [docs/specs/001-lecture-localization/spec.md](docs/specs/001-lecture-localization/spec.md); the staged implementation plan is in the same directory.
